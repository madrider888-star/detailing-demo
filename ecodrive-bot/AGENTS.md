# EcoDrive Auto Photo Bot — контекст для агента (Codex)

Этот файл — полная передача проекта. Прочитай его целиком перед любой правкой.

## 1. Что это и кто владелец

Корпоративный Telegram-бот автосалона **EcoDrive Auto** (сайт ecodrive.in.ua, Украина).
Сотрудник отправляет фото автомобиля и получает готовый JPEG для объявления (AutoRIA).

Владелец — не программист. Объясняй ему всё простыми шагами, по одному действию за раз,
давай команды целиком для копирования и всегда с `cd ~/detailing-demo/ecodrive-bot && ...`
в начале (веб-консоль сервера при переподключении открывается в домашней папке).

**Главное правило продукта:** не менять сам автомобиль. Форма кузова, фары, эмблемы,
стекло, ракурс, кадрирование остаются как в исходнике. Менять только то, что выбрал
сотрудник.

Операции (главное меню бота `@ecodrive_photo_bot`):

| Кнопка | Операция | Чем делается сейчас |
|---|---|---|
| 🔢 Заменить номерную табличку | `plate` | `PLATE_PROVIDER=openai`: OpenAI по маске; запасной вариант — OpenCV |
| 🏙 Заменить фон | `background` | AI-провайдер — **сейчас mock** |
| 🛞 Заменить колёсные диски | `wheels` | AI-провайдер — **сейчас mock** |
| 🎨 Изменить цвет салона | `interior_color` | AI-провайдер — **сейчас mock** |
| 📂 Мои обработки / ℹ️ Инструкция | — | — |

Mock возвращает исходное фото с пометкой `MOCK · <operation>`.

## 3. Стек и архитектура

Python 3.12 · aiogram 3 (FSM в Redis) · FastAPI (`/health`, `/ready`) · PostgreSQL 16 +
SQLAlchemy 2 + Alembic · Redis + ARQ (очередь) · OpenCV + Pillow · S3 (SeaweedFS в compose;
MinIO не используем — его образы больше не публикуются) · Docker Compose · pytest · ruff · mypy strict ·
structlog (JSON, секреты маскируются).

```
Telegram → bot (aiogram) → PostgreSQL / S3 → Redis (ARQ) → worker
worker → ImageEditingProvider (opencv | openai | mock) → нормализация JPEG → Telegram (документ)
```

Сервисы compose: `postgres`, `redis`, `s3`, `migrate` (одноразовый), `bot`, `worker`, `api`.

## 4. Номерная табличка — что уже сделано (история)

1. Детекция: `ContourPlateDetector` (без нейросети), уточнение 4 углов по краям, учёт
   синей EU-полосы. Точность на тестах ≤ 2 px. Неуверенно (< `PLATE_CONFIDENCE_THRESHOLD`,
   0.55) → статус `needs_review` и кнопки «другое фото / вручную (скоро) / оператору».
2. Наложение (`overlay.py`): гомография по углам, подстройка яркости и теней по карте
   освещения исходного номера, размытие и зерно под исходник, alpha blending.
3. Исправлено: цветной исходный номер (жёлтый или зелёный) больше не красит табличку.
4. Владелец прислал свой макет (`ecodrive_plate.png`): чёрная скруглённая табличка, зелёный
   логотип, «ECODRIVE / AUTO», пропорции ≈ 2.52:1. Эталон того, как должно выглядеть, —
   фото BYD на ecodrive.in.ua: табличка ставится на место номера в **своих** пропорциях.
5. Первая версия с этим макетом растягивала его на всю ширину номера → получилось
   «огромное и корявое» (высота ≈ 1.84 × номер). Сейчас:
   - высота макета = `PLATE_TEMPLATE_HEIGHT_RATIO` × высота номера (по умолчанию 1.5);
   - ширина — по пропорциям макета; центр — в центре номера; расчёт в реальных
     пропорциях номера 520×112 мм (поэтому перспектива корректна);
   - видимые остатки старого номера закрашиваются `cv2.inpaint` + зерно;
   - светлый кант по краю, лёгкий блик сверху, мягкая тень снизу.
6. Владелец забраковал и это («жирное, а не растянутое в длину»): табличка должна быть
   **ровно по длине и высоте старого номера**. Сейчас по умолчанию `PLATE_TEMPLATE_FIT=plate`:
   табличка занимает контур номера (+3 %/4.5 % запаса), `fit_template` удлиняет чёрный фон
   макета (углы и кант не трогает), логотип не растягивается — по центру, до 1.15× своего
   размера. `PLATE_TEMPLATE_FIT=logo` — прежнее поведение (пункт 5). Макет в форме номера
   (≈ 520×112) растягивается как есть.

**Режим OpenAI (`PLATE_PROVIDER=openai`, `app/services/image_editing/openai_plate.py`):**
0) детектор находит кандидатов, vision-модель (`OPENAI_VISION_MODEL`, gpt-5,
`plate_picker.py`) по превью с пронумерованными рамками выбирает номер машины; если ни один —
`needs_review`; если модель недоступна — самый уверенный кандидат. Причина: на реальном фото
детектор выбрал табличку на бордюре вместо жёлтого номера;
1) табличка ставится программно (точный макет, пропорции, старый номер закрашен);
2) в OpenAI уходит квадратный фрагмент вокруг номера (без потери резкости) с маской-полосой;
3) `PLATE_AI_MODE=lighting` (по умолчанию): от модели берётся только сглаженное освещение
(свет, блики, тень), геометрия и логотип — строго из макета. `auto` брал пиксели модели при
корреляции ≥ `PLATE_AI_MIN_SIMILARITY` (0.75), но на реальном фото исказил геометрию
таблички — владелец забраковал, по умолчанию не включать.
История: версия, вклеивавшая пиксели модели, давала размытый, перерисованный и обрезанный
логотип — к ней не возвращаться. Если номер не найден — `needs_review`; если OpenAI
недоступен — результат шага 1.

Размер таблички = размер старого номера (`PLATE_TEMPLATE_FIT=plate`). `PLATE_TEMPLATE_HEIGHT_RATIO`
действует только при `PLATE_TEMPLATE_FIT=logo`.

## 5. Твоя зона: визуал и генерация через OpenAI

Подключение реальной генерации фона, дисков и салона:

1. Владелец создаёт API-ключ на platform.openai.com (нужен баланс).
2. На сервере в `.env`:
   ```
   IMAGE_PROVIDER=openai
   OPENAI_API_KEY=sk-...
   OPENAI_IMAGE_MODEL=gpt-image-2
   OPENAI_IMAGE_QUALITY=high
   OPENAI_INPUT_FIDELITY=high
   ```
3. `cd ~/detailing-demo/ecodrive-bot && docker compose up -d` — бот и воркер перечитают `.env`.

Как устроен провайдер (`openai_provider.py`): модель по умолчанию **gpt-image-2** (апрель
2026). Холст считается под пропорции исходника, почти в исходном разрешении
(`OPENAI_IMAGE_MAX_EDGE`, по умолчанию 3840; стороны кратны 16, ≤ 3:1, 0.65–8.3 Мп).
`input_fidelity` для gpt-image-2 не отправляется (иначе 400). Для gpt-image-1 — старые
фиксированные размеры 1024/1536 с полями. Референсы (диск, фон) уходят вторым изображением.
Используются тайм-аут, повторы с backoff (429/5xx/сеть) и понятные ошибки для модерации и ключа.

Что стоит улучшить в первую очередь:
- **Фон:** чтобы автомобиль был пиксель-в-пиксель, лучше сегментировать машину
  (маска) и после генерации вклеивать исходные пиксели автомобиля обратно.
  Тогда модель фактически меняет только фон.
- **Диски / салон:** маска области (колёса / кожаные поверхности) в `images/edits`
  и обратная вклейка всего, что вне маски.
- **Фоны:** заменить заглушки в `assets/backgrounds/` реальными фото студий
  (1920×1280+, без машин и людей). Пресеты — в `BACKGROUND_PRESETS` (`operations.py`).
- Промпты меняй только в `app/prompts/builder.py`. Негативные правила (не менять марку,
  кузов, фары, решётку, стекло, эмблемы, не добавлять текст, не менять ракурс) — обязательны.

Бот общается с OpenAI сам, по ключу из `.env`. Агенту доступ к Telegram для этого не
нужен: чтобы проверить результат, владелец отправляет фото боту и присылает скриншот.

## 6. Обязательные ограничения

- Не создавать функций обхода модерации AutoRIA, детекторов AI или скрытия редактирования.
- Не удалять C2PA и видимые отметки. «Візуалізація» ставится на фон, диски и салон;
  оригинал хранится отдельно (кнопка «Скачать оригинал»).
- Изменения цвета, дисков и комплектации — только как визуализация реально предлагаемой
  конфигурации.
- Секреты — только в `.env`; ключи не логировать (маскировщик в `app/core/logging.py`).

Локально (в `ecodrive-bot/`):

python3.12 -m venv .venv && .venv/bin/pip install -e ".[dev]"

(см. `tests/test_plate.py`, синтетические сцены в `tests/synthetic.py`) и сам посмотри
на картинку результата.

## 8. Как доставить обновление на сервер (сейчас)

Репозиторий приватный, а у сервера нет доступа к GitHub. Пока делаем так:
1. Владелец: GitHub → Settings → Danger Zone → Change visibility → **Public**.
2. Веб-консоль сервера:
   ```
   cd ~/detailing-demo/ecodrive-bot && git pull && docker compose up -d --build && echo ГОТОВО
   ```
3. Владелец: Change visibility → **Private**.

Лучше настроить на сервере **deploy key** (read-only SSH-ключ репозитория) и сменить
remote на `git@github.com:madrider888-star/detailing-demo.git`. Тогда переключать
видимость не нужно.

Полезные команды на сервере:
```
cd ~/detailing-demo/ecodrive-bot && docker compose ps
cd ~/detailing-demo/ecodrive-bot && docker compose logs --tail 50 bot worker
cd ~/detailing-demo/ecodrive-bot && nano .env          # правка настроек
cd ~/detailing-demo/ecodrive-bot && docker compose up -d  # применить .env
```
