# Apex Detailing

Demo website for a fictional premium car detailing studio, built with Claude Code.

Apex Detailing is a paint protection and appearance studio in Odessa: ceramic coatings,
paint protection film, measured paint correction and interior restoration. The business,
its people, its reviews and its prices are all invented — this is a front-end demo, not a
real company.

**Stack:** Next.js 16 (App Router) · React 19 · TypeScript (strict) · Tailwind CSS v4.
No UI kit, no animation library, no icon package — the only runtime dependencies are
`next`, `react` and `react-dom`.

## Running it locally

```bash
npm install
npm run dev        # http://localhost:3000
```

Other scripts:

| Script              | What it does                                              |
| ------------------- | --------------------------------------------------------- |
| `npm run dev`       | Development server with fast refresh                       |
| `npm run build`     | Production build (static except `/contact`)                |
| `npm start`         | Serve the production build                                 |
| `npm run lint`      | ESLint, flat config, `eslint-config-next`                  |
| `npm run typecheck` | `tsc --noEmit`                                             |
| `npm run media`     | Regenerate the artwork in `public/media` from source       |

## Routes

| Route               | Rendering | Notes                                              |
| ------------------- | --------- | -------------------------------------------------- |
| `/`                 | Static    | Hero, popular services, before/after, process, FAQ |
| `/services`         | Static    | All twelve services, grouped by category           |
| `/services/[slug]`  | SSG × 12  | `generateStaticParams` from the content layer      |
| `/pricing`          | Static    | Six pricing groups plus vehicle size tiers         |
| `/gallery`          | Static    | Filterable grid with a lightbox                    |
| `/about`            | Static    | Story, values, equipment, products                 |
| `/contact`          | Dynamic   | Reads `?service=` to preselect the booking form    |
| `/sitemap.xml`, `/robots.txt`, `/opengraph-image`, `/services/[slug]/opengraph-image` | Static | Generated by Next |

## Project structure

```
scripts/
  generate-media.mjs      Draws every image in public/media as an SVG scene
src/
  app/                    Routes only — thin pages that compose sections
    layout.tsx            Fonts, metadata defaults, header/footer, JSON-LD
    services/[slug]/      Dynamic service page + per-service OG image
    sitemap.ts robots.ts opengraph-image.tsx icon.svg
  components/
    layout/               Header (responsive nav), Footer, Logo
    sections/             Hero, PopularServices, ComparisonShowcase, BeforeAfter,
                          WhyChooseUs, Materials, ProcessSteps, Testimonials,
                          Faq, CTASection, GalleryGrid, PageHeader
    cards/                ServiceCard, PricingCard, TestimonialCard
    forms/                BookingForm
    ui/                   Button, Section, SectionTitle, Badge, SpecList,
                          Accordion, Reveal
  content/                Typed data layer — the single source of truth
    site.ts services.ts pricing.ts gallery.ts testimonials.ts home.ts about.ts
  lib/                    cn(), price formatting, metadata helpers
  types/                  Shared domain types
```

Three ideas hold the structure together:

1. **Content is data, not markup.** Services, prices, reviews and gallery entries live in
   `src/content` as typed objects. `/services`, `/services/[slug]`, the pricing page, the
   footer links, the sitemap and the booking form's service dropdown all read from the
   same arrays, so adding a service is a single edit.
2. **Pages compose, components render.** Route files hold almost no markup — they arrange
   section components. A section is reused across routes rather than duplicated.
3. **Artwork is generated, not fetched.** `scripts/generate-media.mjs` draws all 39 images
   (a lit studio scene with three body silhouettes, plus macro shots of beading, polish,
   leather, film weave, tinted glass, headlight optics and wheels). Nothing loads from a
   third-party host, so there is nothing to 404 and no image licensing to worry about.

## Design language

Dark carbon surfaces (`#050607` → `#1b2024`), mist-grey typography and a single brass
accent used only for eyebrows, active states and small numerals. Display type is Archivo,
body is Inter, both self-hosted through `next/font`. Glass effects appear in exactly two
places — the scrolled header and image overlay chips. Motion is a single fade-up on scroll,
disabled under `prefers-reduced-motion`.

## Accessibility & SEO

- One `<h1>` per route, no heading-level jumps, semantic landmarks, skip link.
- Every control is keyboard operable: the before/after slider is a real `role="slider"`
  with arrow-key support, the lightbox closes on `Escape`, the accordion uses proper
  `aria-expanded`/`aria-controls`.
- Scroll-reveal content is forced visible when JavaScript is off.
- Per-route canonical URLs, Open Graph and Twitter cards, PNG social images generated at
  build time, `LocalBusiness` and `Service` JSON-LD.

## Known limits

The booking form has no backend — it validates and confirms in the browser, and says so.
Imagery is illustrative vector artwork rather than photography.
